The question is not "does this work on average". A strategy that made everything in one regime

one already made elsewhere:

- **Worst era, not the mean** — averaging is the one summary that cannot see a regime-dependent

- **Eras are GIVEN, not discovered.** Choosing a boundary after seeing the returns fits the

An era with too few observations is reported as **unmeasured** rather than scored or dropped:
scoring it makes the verdict swing on noise, dropping it silently shrinks the test. An
unmeasured era blocks stability exactly as a failing one does — neither has been shown to work.
Returns belonging to no era are counted too, for the same reason the ratio check reports its
skips.

## Beats-declared-null — one check, three falsifiers

**Red first**: `ModuleNotFoundError: No module named 'pips.validation.incremental_value'`.

Three of the sixteen unbound falsifiers are one question in three costumes — A04's *"reject if
residualization adds no value over raw reversal"*, A05's *"reject if it is not distinct from
market direction"*, A08's *"reject if direction adds no information beyond a volatility
forecast"*. And every one of those baselines is **already written down**: rule 5 makes each spec
declare its `null_models` before the search, and the parents are named there in so many words.

So the check does not choose a baseline. **It requires the caller to name one the spec
pre-registered** — the difference between testing a claim and constructing a comparison the
alpha wins. Coverage: **19 bound, 13 unbound of 32**.

Paired, not two independent samples: the alpha and null see the same periods, and discarding
the pairing inflates the variance. A tie is a FAILURE, because the falsifiers make "adds no
information" the rejection condition and the burden sits on the alpha.

### The branch that held two different answers

A mutation showed a tie and a constant non-zero difference shared one code path *and one
answer* — both reported NOT MEASURED. They are not the same:

- A difference identically **zero** is perfectly measured. The alpha adds exactly nothing,
  which is the falsifier's condition met, not a failure to look.
- A **constant non-zero** difference is genuinely unassessable — there is no dispersion to
  judge it against.

Collapsing them conflates *we could not tell* with *we could tell, and the answer is no*, which
is the distinction this project keeps re-establishing. Split, with a test each.

### Two fixtures that could not fail

- **"A tiny lift inside the noise"** added a *perfectly constant* lift, making the paired
  difference identical every period — not a tiny edge but the most informative signal
  imaginable, t = 1.4e14. Fourth time this session a tidy arithmetic fixture produced
  degenerate statistics. The lift now carries its own noise.
- **The residue test** used pure Decimal arithmetic, which is exact, so variance was genuinely
  zero and `variance <= 0` caught it too — the mutation survived. Rebuilt through
  float → str → Decimal, which is how the real fixture produced it: the `str()` rounds to 17
  digits, a "constant" lift lands on two distinct Decimals, and the variance is 3.1e-37 —
  sqrt 5.6e-19, below `RESIDUAL_EPSILON` but emphatically not zero. That is the gap the
  epsilon exists for, and the same one the alpha plugins found when three identical names

## Family sensitivity — A02's falsifier, and A02 fully bound

**Red first**: `ModuleNotFoundError: No module named 'pips.validation.family_sensitivity'`.

A02 pre-registered *"Reject if only one lookback works"*. Its plugin already refuses a
single-lookback configuration at construction and averages the declared lookbacks rather than
picking the best — but that guards against **searching**, and says nothing about whether the
result survives when each value is looked at alone. Averaging is in fact what hides the
failure: one spectacular lookback and three dead ones produce a mean that looks fine.

**Contiguity is reported, not required.** If 5 and 40 clear the bar while 10 and 20 do not,
that is a suspicious shape — a real effect is usually smooth in its own parameter, which is
plateau-centroid's argument for 2D surfaces. But A02 registered *"only one works"*, not *"the
working set must be contiguous"*, and **holding an alpha to a stricter bar than it registered
is changing the test after the fact**, in the same way that loosening one would be. The gap is
surfaced and does not fail. A mutation that made contiguity a pass condition is killed by a
test asserting exactly that.

Zero working and one working are reported differently: *"nothing works, the effect is absent"*
and *"only one works, a single-parameter artefact"* lead somewhere different, and a single
boolean loses that.
