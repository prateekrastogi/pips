# 2026-09-02

## M6 — bronze becomes silver `[C-SILVER-01]`

**Red first**: `ModuleNotFoundError: No module named 'pips.data.silver'`.

Yesterday ended with "the synthetic fixtures are near the end of what they can support; the next
real step is bars from Breeze". Surveying arb-vm before committing to that found something
better than fetching more: **there is already real data nobody is using.** Bronze holds three
trading days of RELIND (Reliance) one-minute bars — 369 rows a day, real OHLCV — and silver and
gold are empty. `normalize_candles` has produced close-labelled integer-paise bars since M4.
Nothing ever persisted them or gave them an identity.

### The vendor code is not the symbol

Bronze is keyed by `RELIND`; the exchange calls it `RELIANCE`. Only **172 of 5,851** instruments
have the two equal, so writing bars under the vendor code would mislabel almost every name — and
the bars would look perfectly ordinary while joining to no universe, cost model or corporate
action. An unresolvable code is quarantined rather than passed through.

ADR-0001 had already settled the other identity question empirically: Breeze is OPEN-labelled and
ingest adds one interval, probed by a price identity rather than by counting candles. A 09:15
candle covers `[09:15, 09:16)`, so it is the bar ending at 09:16. Off by one interval is a
one-bar lookahead, which backtests love.

### Four survivors, all the same shape

The mutation run was unusually informative. `not-ok-written-as-data`, `empty-bars-promoted`,
`unsorted-files` and `unsorted-rows` all survived, and every one for the same reason: **my test
could not tell the guard from the fallback that happened to catch the same case.**

- Deleting the response-kind check still quarantined the bad replies — via the empty-bars
  fallback below it. "There is some reason" passed with the guard gone; what distinguishes them
  is what the reason SAYS, so the test now asserts the classification appears in it.
- `if not bars` is only reachable on an OK reply whose candles all fall outside the session —
  pre-open prints — which no test had.
- The row sort made the file sort look redundant: rows come out ordered either way. But the
  QUARANTINE list is not sorted afterwards, so it is the thing that carries the filesystem's
  order into the report, and a quarantine list that differs between machines is a report two
  people cannot compare. That is what makes the file sort load-bearing.
- Both order tests originally called the function twice and compared, which varies nothing —
  `rglob` yields the same order both times. Monkeypatched to reverse.
