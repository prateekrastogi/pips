## Tick 1 (continued) — M0.5 container verify + a vacuous-gate fix

**Container.** `docker compose build research` failed first on `rustup-init`: `--component
clippy rustfmt` is not a list, it needs one `--component` per component. Fixed; rebuilt;
`docker compose run --rm research make ci` → **ci: green**. That is M0.5's first Verify met.
Added `.dockerignore` (rule 14: no data, no repo history baked into an image) and re-verified
green. Image `pips/research:dev`, 2.29GB (python 3.12 + rust 1.90 + pandoc).

**A gate that could not fail.** With `.git` excluded from the image, in-container `tdd-check`
printed `OK: no commits ahead of main` — it passed because it could not see history, which is
precisely the vacuous-test failure mode ADR-0009 exists to prevent. Fixed test-first:

```
$ # RED — tests written before the implementation
$ uv run pytest tests/unit/test_tdd.py
E   ImportError: cannot import name 'NotAGitRepositoryError' from 'pips.ledger.tdd'

$ # GREEN — after adding NotAGitRepositoryError / UnknownBaseRefError and the CLI branches
$ uv run pytest
85 passed in 1.54s
```

`git_commits` now raises rather than returning `[]` when it cannot look: an empty result
means "nothing to flag", never "I could not look". Three behaviours, all exercised:

```
real repo      -> tdd-check OK: 1 commit(s) on this branch are test-first     (exit 0)
no git repo    -> tdd-check SKIPPED: ... this run proves nothing.             (exit 0, loud)
unknown base   -> tdd-check FAILED: unknown base ref 'origin/nope'            (exit 1)
```

**Jenkins → BLK-0001, escalated: human.** A Jenkins controller is running (`keeper-jenkins`,
localhost:8080) and has `/var/run/docker.sock` + a docker CLI, so the `Jenkinsfile` stages

credential, which the constitution puts in the human-only set, so this is not a §10.4

**Reference extraction (M0 deliverable).** `docker compose -f docker-compose.yml -f
