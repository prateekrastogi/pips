## Tick 4 — M2 chunk: as-of panel view + the permanent leakage canary

One coherent chunk of M2 (LOOP.md §1.5), not the whole milestone: the causality guard and the
tripwire that proves it. Calendars `[C-SESS-01]` and trial identity `[C-ID-01]` remain for
later ticks, and their ledger rows are deliberately NOT flipped.

**`AsOfPanelView`** — the production read path over Polars panels. Three bans are mechanical
rather than advisory, because each is a leak reviewers miss: `day_*` / `*_full_day` (full-day
aggregates, unknowable intraday), `smoothed_*` (`P(S_t | F_T)`, reads the future by
construction), and negative shifts. Banned columns are dropped from `visible()` too, so the
obvious bypass — take the frame instead of calling `column()` — yields a frame that does not
contain them. `join_asof_safe` *refuses* a right frame carrying future rows rather than
filtering it: silently filtering would hide that the caller believed it held information it
cannot have, and that belief is the bug.

**18 adversarial tests**, written first: forward shift, future join, banned-field access via
both paths, the exactly-at-decision boundary, empty visible window, earliest-fill strictly
after the decision.

**The canary — three cheats, one per ban**, kept in the suite forever (§7). Each must be
spectacular unsafely and refused in production. Two controls stop the suite proving nothing:
an honest alpha must SURVIVE the same path (else a guard that refused everything would pass),
and must NOT be spectacular (else the threshold separates nothing).

**RED→GREEN, and one genuine fix (§7.1).**
```
$ uv run pytest tests/unit/core/test_asof_panel.py
E   ImportError: cannot import name 'AsOfPanelView'                       <- RED
$ uv run pytest tests/property/test_leakage_canary.py
E   ModuleNotFoundError: No module named 'pips.alphas.canary'             <- RED
```
Then a second, more useful red: two canaries scored |IC| 0.87, under the 0.90 bar. The test's
own message says *fix the canary, never the threshold*, so the fixture was rebuilt rather
than the bar lowered. Root cause was real: the first fixture used an alternating drift, where
price level and next-bar velocity are ~90 degrees out of phase and correlate to nearly zero.
AR mean reversion (`d_{t+1} = -0.9 d_t`) makes the next move a linear function of the current
deviation, so a feature that knows the day's centre scores perfectly. The smoothed-state
canary was also binary, which ties most ranks and caps achievable IC; made graded.

```
next_bar_return        |IC| = 1.0000
distance_to_day_vwap   |IC| = 1.0000
smoothed_regime        |IC| = 1.0000
honest: lagged volume  |IC| = 0.0071      <- the control, comfortably below 0.90
```
The honest control is lagged VOLUME, not lagged close: on a mean-reverting path the level
genuinely predicts the next move, which is a property of the fixture and not a leak, and
would have failed the control for the wrong reason.

## Tick 5 — M2 chunk: exchange calendar + session states [C-SESS-01] → enforced

**Modelled CAS as a separate venue, not a session state.** §3.15 lists six states including
`CAS` at 15:15–15:35, but the continuous session ends 15:30 — they overlap in wall clock, so
CAS cannot be a phase of the continuous session. It is the closing auction, a different venue,
and the code says so: `in_cas_window()` is independent of `session_at()`, and an instant at
15:20 is simultaneously in the CAS window and `FLATTEN_ONLY` on the continuous tape. Disabled
as an alpha venue per ADR-0004.

**The broker cutoff is a required argument, not a constant.** §3.15 forbids a hard-coded time;
`session_at(ts, broker_cutoff_ns=...)` has no default, so no caller can accidentally get one.
The load-bearing test is `test_the_broker_cutoff_is_data_not_a_constant`: the same instant must
resolve to `LATE_CTS` under a 15:25 cutoff and `FLATTEN_ONLY` under 15:12. If that ever stops
holding, a square-off time has been baked in — which is the failure that breaks silently on the
day a broker moves it.

**Holidays shipped empty, on purpose.** Inventing plausible NSE 2026 dates would be worse than
shipping none: an invented holiday is indistinguishable from a verified one at the point of
use, and would fabricate or delete a trading day in every backtest spanning it. The calendar is
effective-dated data like a fee schedule (rule 6) — it carries `holidays_source` and
`holidays_verified_on`, reports `holidays_verified: false`, and `require_verified_holidays()`
raises. Unverified does not mean unusable: P0–P2 runs on fixtures and needs the session
structure long before the list is sourced at M6.

## Tick 6 — M2 complete: trial identity [C-ID-01] → enforced

**The hash is taken over the model's own dump, not a hand-written tuple**, so a field added to
`TrialIdentity` is hashed by construction. The guard that matters is
`test_every_field_changes_the_trial_id`, parametrised over the model's OWN field list: a field
added later but omitted from the hash fails there. The failure mode it prevents is silent —
two distinct trials that hash alike collide, and the second returns the first one's cached
result, which looks like a successful cache hit rather than a bug.

**A real defect the tests caught.** The first implementation hashed `model_dump(mode="json")`.
Pydantic's JSON serialiser turns a non-finite float into `null` by default, so a parameter of
`inf` and a parameter of `None` produced the SAME trial id — two different trials sharing one
identity and one cached result. `[C-NUM-01]` is explicit that NaN and infinities do not cross
a schema boundary. Fixed by hashing the python-mode dump, where the float survives and
`canonicalize` refuses it. The same strictness now rejects any parameter type the canonical
encoding has no definition for, rather than stringifying it into a collision.

```
$ uv run pytest tests/unit/core/test_trial_identity.py
E   ModuleNotFoundError: No module named 'pips.core.trial'                        <- RED
...
FAILED test_a_non_finite_parameter_is_refused - DID NOT RAISE ValueError          <- RED again,
FAILED test_every_field_changes_the_trial_id[runtime_versions]                       usefully
$ uv run pytest tests/unit/core/test_trial_identity.py -q
.............................                                                     <- GREEN (29)
```
The second red was the valuable one: it surfaced the inf→null collision, which no amount of
reading the code would have shown.

**The cache is not the registry.** `TrialCache` only avoids recomputing an identical trial;
`[C-REG-01]` (M11) is the append-only record of *every viewed trial* (rule 4). A cache hit is
not a reason to skip registering the trial, and the docstring says so, because conflating them
is how "deleted trials" stop being counted. Each entry stores the identity beside the result —
a result without a resolvable identity is not evidence (rule 3).

**Rule 5 is enforced at entry, not reviewed later.** A spec without null models does not
validate; a spec without a written falsifier does not validate; and a "falsifier" that names
no perturbation and no outcome — `"looks bad"` — is refused too, because it could not be
evaluated at the only time it would matter. A discipline that is optional at the point of
entry is not a discipline.

after removing the common move — not winner-chasing. So the test asserts that when every name
moves identically, the alpha produces no signal. An implementation that ranked raw returns
would sail through a smoke test and fail this, which is exactly the mechanism the card denies.

**Scope stated rather than implied.** The card removes market *and sector* moves via rolling

sector neutralization" is precisely the test this implementation cannot yet run.

**The shuffled-future control, and what it is not.** It catches a measurement pipeline
reporting an edge where none exists. It does NOT catch lookahead — a cheating alpha has a
genuinely strong in-sample relationship and clears a permutation test comfortably. That is the
as-of view's job and the canary's. `test_a_cheating_alpha_passes_this_control_and_that_is_expected`

## Tick 15 — M12 complete: nine pre-registrations, and a check I had to make weaker to make honest

All nine T1 wave-1 families (A01-A08, A12) are now pre-registered, with every falsifier
**transcribed from its reference card** rather than composed here.

**The structural test that matters is A05 vs A06.** §5 requires gap continuation and gap
reversal to be separate and "never chosen ex post", and A06's own card says "reject if
continuation and reversal rules are selected ex post by realized sign". The failure this
prevents is common and subtle: one gap rule whose sign is decided after seeing which way the
day went, presented afterwards as two strategies. The test asserts independent hashes, distinct
parameter grids and distinct null models, which makes that structurally impossible rather than
merely discouraged.

**A06 treats missing event metadata as EXCLUSION, not "no event".** The card makes the
no-event flag mandatory, and with no PIT event masters until M6 the conservative reading is to
drop the name — assuming "no event" would silently trade exactly the names most likely to have
had one.

**New schema field: `falsifiers_deferred`.** A falsifier that is pre-registered but not yet
runnable (A03's midquote leg needs the T2 quote archive; A06's event metadata needs M6; A12's
calendar-era stability needs 3y of backfill) is declared as such, with what it awaits. A spec
whose strongest rejection condition is unrunnable is weaker evidence than one whose conditions
can all be applied, and a reader should not have to work that out. A test also requires every
alpha to keep at least ONE runnable falsifier — an alpha that cannot be falsified at all would
enter the funnel with no way to fail, which is exactly the status rule 5 exists to prevent.

**The falsifier validator: twice too strong, and the fix was to weaken it.** It first demanded
the literal phrase "reject if" and rejected the reference's own A12 falsifier. Widened to a
"referent vocabulary", it then rejected A07's. The pattern was clear: each failure would be
fixed by widening the list, and a list widened until it stops rejecting anything checks
nothing. **A check that refuses the source document is broken; a check that accepts everything
is theatre.** So it was narrowed to what is genuinely mechanical — an action word and a clause
rather than a fragment — with the module stating plainly what it gave up on and where the real
enforcement lives (human review at pre-registration, and M16's battery actually applying each

## Tick 16 — M13: the S1 statistics, and a 7x over-rejection they caught

**Null-search calibration earned its place immediately.** Destroy features and labels, run the
whole S1 chain — rank IC, Newey-West t, p-value, BH step-up — and the fraction of SEARCHES
producing a survivor should sit near q. First run: **0.70 against a nominal q of 0.10**.

The cause was a normal p-value applied to a t-statistic computed on ~10 IC observations. At
that sample size the t-distribution's tails are far heavier than the normal's, so the normal
approximation manufactures significance out of nothing. Fixed properly — a real Student's t via
the regularized incomplete beta (continued fraction), written out rather than approximated,
because the approximation is exactly what it replaces. After the fix:
```
q=0.05 -> survivor 0.05   q=0.10 -> 0.08   q=0.20 -> 0.17
```
No individual number looked wrong before the fix. Every p-value was plausible, every t-stat
reasonable. Only the end-to-end rate could see it — which is the argument for having this check
at all rather than trusting the components.

**A test of mine was wrong, and the code was right.** `test_bh_on_the_textbook_example`
truncated Benjamini-Hochberg's 15-value example to 10 and expected 4 rejections. But n enters
the threshold k/n·q, so dropping the insignificant tail makes every remaining test EASIER to
reject and the correct answer becomes 8. Restored the full example, and added a test pinning
the mechanism as a property — because it is the arithmetic form of §7's "hidden/deleted
trials": a trial you stop counting makes every other trial easier to promote.

**Newey-West is here because the naive alternative flatters.** Minute-bar IC series are
autocorrelated, so an OLS t reports confidence nobody earned — the same error §7 names as
"minute-Sharpe annualized as independent". The test asserts NW < naive under positive
autocorrelation, which is the property, not just that it runs.

**FDR is applied within family × universe**, and a test asserts a family with more tests faces
a stricter bar. Pooling everything would penalise a family for another's tests; correcting
nothing would promote the best of N.

**`ic_half_life` returns None on a non-decaying curve** rather than a number. Inventing a decay
rate for something that is not decaying puts a plausible parameter into a report with no
referent.

**s1-smoke states its own coverage:** 9 specs registered, 1 with a compute plugin, 8 awaiting
one. A sweep that silently skipped what it could not run would correct over fewer tests than
were proposed — the same failure as truncating the BH example.

cargo test, determinism, ledger-check 26 rows (12/3/11).

## Tick 17 — A02/A03/A04 plugins, and rounding noise sold as signal

**A mechanism test caught a real bug in shipped code.** Three *identical* names — same prices,
same returns, therefore zero residual by construction — were scoring 3.115 under A04.

The cause: `Decimal` carries 28 significant digits, so `(r + r + r) / 3` does not return
exactly `r`. It leaves ~1e-30 behind. Every residual was then ~1e-30, their sigma was ~1e-30
too, and `residual / sigma` turned pure rounding noise into a score of order 1. A perfectly
co-moving group produced confident dislocation signals out of arithmetic.

A01 had shipped with the same defect two ticks earlier and passed its own neutralization test
— but only by accident: `robust_z` zeroes its output when the MAD is zero, so the final step
masked the noisy intermediates. A04 divides directly and had no such shield. Fixed at source
with a `RESIDUAL_EPSILON` of 1e-18, which sits ~12 orders above the residue and ~13 below the
smallest real move available (one 5-paise tick on a Rs2,500 stock is 2e-5), so it can only
ever remove noise. All three alphas now return exactly 0 on identical names.

**Shared residualization is deliberate.** A01 claims residual CONTINUATION and A03 claims
residual REVERSAL, so they must disagree in sign on the same data — and they share
`_common.cross_sectional_residuals` precisely so that disagreement is between two hypotheses
rather than between two implementations of the word "residual". The contradiction test now
shows SHOCK at A01 +80.96 / A03 -74.92 and Q3 at -1.00 / +3.16.

**A04's distinguishing test is the one the card demands.** Its estimand is the conditional
error-correction response of a factor-relative state, explicitly "not the unconditional
tendency of a price to revisit a moving average". A steadily trending name sits above its own
moving average forever, so an MA-reversion implementation shorts it forever; measured against
a factor-relative state, a name whose peers trend with it is dislocated from nothing and says
nothing.

**Three of my own test fixtures were wrong, in instructive ways.** One placed a dislocation at
bar 37 while the view sat at bar 35 — the as-of guard correctly hiding it from my own test.
One treated A03's *gated silence* as agreement in sign; silence is not agreement. And one used
a perfectly linear divergence whose near-constant residual makes sigma ~0 and z enormous — so
"entry_z=99" was not a wide band at all. That last one also revealed why A03 needs five names
to test: under MAD scaling a three-name cross-section structurally cannot reach a z of 1.5, so
testing it would have required a tail below A03's own pre-registered domain of 1.5-3.5 — that
is, testing a configuration the spec forbids.

cargo test, determinism, ledger-check; `make s1-smoke` now covers 4 of 9 specs, and says so.

## Tick 22 — M4 closed: first real campaign, and three defects only running it could find

`6/6 fetched · 492 KB bronze · 370 rows/session · resume costs zero calls`

The code had been green for two ticks. Running it against live Breeze on arb-vm found three
things no test would have, each a silent failure rather than a loud one.

**1. A stale image tag.** `docker compose run research` resolved `pips/research:dev` — an
hour-old build from before the command being invoked existed, so the CLI printed help for a
subcommand it did not have. The rail publishes SHA-tagged images and nothing refreshed the
fallback. For a data campaign that is worse than confusing: a manual run would write bronze
using whatever normalizer was in the stale image, and those records would be indistinguishable
from correct ones. Fixed structurally — the fallback is `current` and the rail republishes it,
with a test parsing both files so they cannot drift.

**2. ADR-0011 was never wired.** The campaign died on `KeyError('BREEZE_API_KEY')`: the ADR had
moved the Breeze token into the repo's `.env`, and compose still pointed the data plane at the
superseded VM-side file. A decision recorded in docs and never implemented — the drift a ledger
exists to prevent, now covered by a test.

**3. The data root fragmented into three volumes.** Compose prefixes volume names with the
project, which it derives from the DIRECTORY. One declaration produced `pips-data` (bootstrap),
`checkout_pips-data` (/srv/pips/checkout) and `verify_pips-data` (a throwaway worktree). The six
records landed in the third, invisible to the runbook, the systemd unit and any backup. The
Jenkins controller taught this exact lesson earlier; this was the same trap on the data plane,
where the cost is fragmented market data. `/srv/pips` is now a host bind and the project name is
explicit. The records were migrated rather than re-fetched.

**A test of mine asserted the opposite of the fix.** `test_compose_points_the_data_root_at_a_vm_volume`
demanded a named volume — written before anything had been run, and running it is what showed
it wrong. Corrected rather than kept alongside the new one: two tests demanding opposite things
is not coverage.

**And a third recurrence of one pattern, finally extracted.** A new guard fired on a COMMENT in
`.env` saying `PIPS_LIVE=1` must never be set there — the third time a text-matching guard here
has matched prose documenting the thing it forbids (Corwin-Schultz, the deploy service list,
now this). Each local fix was easy, which is why I kept re-deriving it. The rule now lives once
in `tests/conftest.py` with all three occurrences in its docstring.
