## Mutation sweep, target fifteen: `data/breeze/campaign.py` — the command that spends the money

The driver behind `pips backfill`, and the one piece of that path still unswept. 14 mutations,
**6 survived**, and the reason they all clustered in one place is stark: **`main()` was never
called by any test.** Every existing test exercised `plan_campaign` and `CampaignPlan`, so the
entire CLI — `--dry-run` and every exit code — was unexercised.

**`--dry-run` was not tested to fetch nothing.** That is the whole purpose of the flag: a date
range is two strings and a mis-typed one is a keystroke away, so the plan exists to be costed
before it is spent. A `--dry-run` that reached the fetcher would spend real quota against a
metered daily budget, on the command whose entire point is not to. The test now asserts the
session is never opened and the fetcher never built — and a control test asserts a *real* run
does reach them, so a `main` that fetched nothing at all could not pass both.

**Every exit code was untested, and the exit code is the scheduler's resume signal.**

- **A rate-limited stop exits 1.** Exiting 0 tells a scheduler the campaign succeeded, so it
  stops re-running — leaving a hole no later QC can tell from a quiet market.
- **A budget stop exits 0**, because spending the day's quota is the plan working. A campaign
  costing three days of quota stops twice on the way to finishing, and a scheduler treating each
  stop as failure would page somebody about a backfill behaving exactly as designed.
- **Which means the exit code cannot carry that difference, so the message must.** The last
  mutant survived precisely there: with the budget branch removed the run still exits 0, but
  prints **"campaign complete."** for a run that stopped with work outstanding. Same
  failure-that-looks-like-success this module is built against, aimed at the operator rather
  than the archive. The test now pins the text, not just the code.
- **Errored keys exit 1** — they were deliberately left unmarked so the next run retries them,
  which only helps if something says a next run is needed.
- **A plan that cannot be costed exits 2**, distinct from 1: nothing was attempted, so nothing
  is pending and retrying is pointless. It must also open no session.

Noted, not acted on: `main` reads `config/breeze.yaml` by a **relative** path while the data root
comes from `$PIPS_DATA_ROOT`, so the campaign is cwd-sensitive in one dimension and not the
other. It fails loudly rather than quietly, which is why it is a note.
