## `config/gates.yaml` cannot claim a gate that nothing enforces

Found mechanically, not by reading prose: a scan for config keys that appear nowhere in
`python/` as an identifier. Yesterday's `candles_per_call` finding was one instance of that
shape, so the question was whether it was the only one.

It was not, and the second one is on the certification bars.

### RED

```
FAILED test_every_threshold_says_what_enforces_it
FAILED test_a_threshold_bound_to_a_ledger_row_equals_it
FAILED test_a_threshold_enforced_by_nothing_says_so_and_means_it
FAILED test_the_four_unenforced_thresholds_are_named
```

### The finding

`config/gates.yaml` called itself *"numeric thresholds the funnel enforces"* and claimed
*"every value here has a matching row in docs/ledger/gates.yaml"*. Both were checkable. Four
values had no ledger row and appeared nowhere in the code:

- `s4_certification.min_test_trades: 400`
- `s4_certification.pairwise_pnl_corr_max: 0.5`
- `p3_gate.net_sharpe_min_zero_cost_line: 1.5`
- `p3_gate.net_sharpe_min_high_cost_line: 1.0`

I checked each against the plausible alternative before calling it: the `400`s in the code are
S1's halving budget in **bars**, not a trade count; `cluster.py`'s correlation threshold is a
caller-supplied parameter on `1 - corr` distance, a different number reached a different way;
there is no net-Sharpe floor anywhere. They are populated numbers that read as live bars and
are enforced by nothing.

**The code is not at risk.** The funnel's bars are bound to `docs/ledger/gates.yaml` by the
ledger-agreement test, so a wrong constant fails. The hazard is the second declaration: this is
the file a person reads, and a number here drifting from the enforced one has nothing to say so.

### The principle the file already half-stated

> Populated as each gate's milestone lands; **empty values are not defaults, they are gaps.**

Right, and incomplete. The inverse is the more dangerous half, because an empty threshold is
obviously missing while a filled one that nothing consults looks exactly like a gate that
passed: **a populated value is not a gate unless something reads it.** That is now in the header
and checked by `enforced_by`, which maps every threshold to the `G-*` row that carries its live
value, to a contracts row, or to `null`.

### The test caught my own first mapping

I mapped `stress.cost_multipliers` → `G-P4-COST15`, which sounds right and is wrong in kind:
that row's `value` is a net-return **floor of 0.0** at one point of the grid ("still positive at
1.5x cost"), and the grid here is the input those points are drawn from. The equality test
failed with `[1.0, 1.5, 2.0] == 0.0` and I corrected both grids to `null`.

Worth recording because it is the first time this session a test I had just written caught *me*
rather than the code — which is the only evidence that the check is doing work.

### Both directions, and an escape hatch that is itself checked

`null` has to stay true or it rots the other way: a bar wired up later while this still says
`null` understates the system, and the next reader — told it is not live — will not look. So
each `null` is checked against the source, and no key it names may appear in `python/`.

That immediately hit a real collision: `delay_bars` exists in `s1.py` as an unrelated function
parameter for the +1-bar stress run. So there is an `unread_name_collisions` map — and a test
that every entry in it is a **real** collision, because "trust me, it is unrelated" is exactly
what this file is trying to stop.
