# BLK-0005 — the shortlist needs spread, and spread is what the shortlist buys

**Opened:** 2026-09-05 · **Status:** RESOLVED 2026-09-05 — owner chose **A+**.

**Resolution.** A three-component pre-rank picks the 500, AND the risk it creates is made
measurable and correctable rather than merely accepted:

* each refresh **verifies** that every U300 name was inside the 500 — the superset property moves
  from *by construction* to *checked on real data*, which is a weaker guarantee honestly stated
  rather than a stronger one silently broken;
* a small **exploration budget** captures names just outside the 500, so the asymmetric risk —
  a tight but modest-volume name that the three-component rank misses and that therefore never
  gets the data which would have shown it — is corrected over time instead of compounding.
  `shortlist.py` is right that "a name missing from it is missing from the archive for as long
  as the archive runs"; rotation is the only thing that ever answers that.
**Blocks:** the 500-name shortlist, and therefore U300 and the 1-minute campaign. Everything
upstream of it now works: daily bars have a home, and three of the four score components exist.

## The circularity, stated exactly

`build_shortlist` cuts the admissible set to N using `liquidity_scores`. `_unmeasurable` — which
mirrors `_usable` — requires `relative_spread` to be finite, and refuses to default it:

> *"Not defaulted to zero: a missing spread read as zero makes an illiquid name look tight, which
> is the flattering direction and the one that costs money."*

Spread is not derivable from daily OHLC at any interval. It comes from 1-second capture, and
1-second capture is budgeted **for the 500 names the shortlist selects**. So:

    shortlist needs spread -> spread needs 1-second data -> 1-second data is bought for the shortlist

With no spread anywhere, `build_shortlist` admits **nobody**. It is not broken; it cannot run yet.

`[C-UNIV-01]` records a circularity already, but frames it as *"the daily inputs ... need bars
this project does not have yet"*. That framing is now out of date: the bars exist, and median
₹-volume, Amihud and gap-rate are all implemented. What remains is structural and survives any
amount of daily data.

## Two documents in this repository disagree about the fix

**`CURRENT.md`'s ordering** says: range-fetch daily for everything -> **rank on the three
daily-derivable components** -> 1-second for a shortlist -> the full four-component score -> U300.
That breaks the circle with a three-component pre-rank.

**`shortlist.py` forbids exactly that**, at length and with a reason:

> *"The score is M7's `liquidity_scores`, unchanged and unweighted by anything here. That is the
> load-bearing choice. The universe is the top N of that same ordering, so ranking the shortlist
> by it makes the shortlist a **superset of every registered universe by construction** — a name
> cannot enter U300 without already being inside the 500, which is the entire reason the number
> is 500 rather than 300. A second, differently-weighted score would break that silently, and
> would be free parameters chosen after seeing the data, which is what `top_n` refuses an
> unregistered N to prevent."*

Both were written deliberately. They cannot both hold.

## What is NOT available as a way out

* **Acquire spread for everyone first.** 1-second over 60 sessions is ~1,380 calls per symbol;
  for the 1,804 names with real history that is ~2.5M calls, the 27.6 quota-days `CURRENT.md`
  already costs. That is the expense the shortlist exists to avoid.
* **Estimate spread from daily OHLC.** Corwin-Schultz is the standard answer and this project has
  already rejected it with evidence: `SAL-0014` records the donor measuring ~135bp against a 13bp
  anchor — an order of magnitude out — and pips carries an AST guard treating any reference to it,
  even from a test, as a reintroduction. That door is closed and was closed on purpose.
* **Default the missing spread.** Precisely what `_usable` and `_unmeasurable` exist to refuse,
  and in the flattering direction.

## The decision

**Option A — a three-component pre-rank chooses the 500** (`CURRENT.md`'s ordering). The superset
guarantee stops holding *by construction* and becomes something to CHECK once spread exists.

  My read is that this is right, and that `shortlist.py`'s own numbers support it: the shortlist
  is 500 against a universe of 300, and that 200-name buffer is exactly the slack a ranking
  difference needs. The owner's 2026-09-03 note on choosing 500 says the buffer is applied *to
  DATA* so "a name entering U300 is already being captured rather than arriving cold". A
  three-component pre-rank makes the buffer do real work rather than being decorative — but it
  must be stated, and the superset property must move from "by construction" to "measured, each
  refresh".

**Option B — hold the shortlist until spread exists by some other route.** Honest, and it stops
the project: there is no other route costed at less than 27.6 quota-days.

**What Option A costs, plainly.** The names picked for capture would be chosen by an ordering
that omits the term carrying the second-largest weight (spread, -0.75). A name that is heavily
traded but persistently wide could enter the 500 and then fail the real score; a tight but
modest-volume name could miss the 500 and never get the data that would have shown it. The
second is the asymmetric risk, because a name missing from the archive is missing for as long as
the archive runs — which is `shortlist.py`'s own argument, pointed at this decision.

## What was NOT done

No pre-rank was written. This was found while starting one, and the module that forbids it says
so clearly enough that building it first and asking afterwards would have been the wrong order.
