## Why "teach promotion the range shape" is the WRONG fix

That was the next unit named in CURRENT.md before this file existed, and it is wrong. It treats
the problem as a missing branch when it is a missing **layer**.

`_INTERVAL_MINUTES = 1`: silver is *definitionally* the one-minute intraday panel. Its bar model
is `(trade_date, close_label)` where the label is an intraday time clipped to the continuous
session. A daily bar has no intraday close label. Handling the range shape without addressing
that would walk every one of the 3,101 records into `normalize_candles`, clip every bar away,
and quarantine them all again — with `no bars survived normalization` instead of `KeyError`. A
worse message for the same outcome, and the appearance of progress.

There is a second reason it is the wrong frame: `normalize_candles` **ignores the candle's own
date** and stamps every bar with the single `trade_date` passed in. Any careless "explode the
range" patch would date three years of bars to one day.

## What is actually missing

Three things, and only the first needs a decision:

1. **A home for daily bars.** Not specified anywhere in `IMPLEMENTATION.md` or the ledger. The
   plan in CURRENT.md says "rank on the three daily-derivable components" but never says where
   those bars live.
2. **A bars → `SymbolStats` path.** None exists: across the whole tree `SymbolStats(` is
   constructed only in tests. `liquidity_scores` is pure and takes them; `snapshot.py` receives
   them from a caller that does not exist.
3. **A three-component ranking that is not `liquidity_scores`.** `_usable` requires all four
   components, and spread is not derivable from daily OHLC at any interval. So the daily
   ranking must be its own function — calling `liquidity_scores` with spread missing is exactly
   what `_usable` refuses, and for a good reason it already states: *"a missing spread read as
   zero makes an illiquid name look tight"*.

## The decision

**Option A — a daily panel beside silver.** Its own root and row shape (one row per
symbol-day, no intraday label), its own QC checks, its own promotion path. Silver keeps
meaning exactly one thing. Costs a parallel path; the two never share a bar model.

**Option B — silver gains an interval dimension.** One panel, rows keyed by interval, the
session clip applied only where an intraday label exists. Fewer concepts, but it changes the
meaning of every existing silver row and every reader of them, and `_INTERVAL_MINUTES = 1` is
currently load-bearing in ways that would need auditing one by one.

My read is **Option A**, because the daily bars exist for exactly one consumer — the liquidity
ranking that picks the 500 — and that consumer wants symbol-day rows, not minute bars. Option B
buys generality that nothing has asked for and puts the certified intraday panel at risk to get
it. But this changes the shape of M5/M6 either way, so it is the owner's call and not mine.

## What was NOT done

No code was written toward either option. Bronze is untouched — `Quarantined` records a reason
and moves nothing (§3.4). The 6 pre-existing day-keyed records promoted normally to 2,216 bars,
so the day-keyed path is confirmed working on real data.
